# ADR 0004 — Правила, находки и доказательства

Статус: принято · 23.10.2026

## Контекст

Ценность продукта — не в том, что модель «прочитала проект», а в находках, которые ГИП проверит за минуту
и которым можно доверять при повторе. Предметных знаний у команды пока нет, поэтому правило должно само
объяснять, что и почему оно проверяет, и быть проверяемым без эксперта.

## Решение

**Правило = код + метаданные + фикстуры.**

| Поле | Что |
|---|---|
| `id`, `version` | например `spds.titleblock.sheet-count`; семантическая версия |
| `family` | комплектность, оформление, увязка, нормы, расчёты, смета, формат подачи — по `bim-data/taxonomies/remark_and_defect_taxonomy.json` |
| `kind` | наличие, параметр, согласованность, ссылка, формат, вручную |
| `severity` | блокирует / существенно / мелочь / к сведению |
| `applies` | юрисдикция, вид объекта, стадия, вид работ, даты, виды документов |
| `basis` | документ индекса норм и пункт, например «ГОСТ Р 21.101-2020, 5.2.2» |
| `why` | почему эксперт это ловит — одна-две фразы |
| `remark` | как это сформулировал бы эксперт — шаблон текста находки |
| `fixtures` | минимальные пакеты «должно сработать» и «не должно» |
| `review` | черновик / проверено практиком (кто, когда) / выпущено |

Из метаданных генерируется **карточка правила** — для рецензента-практика и для обучения команды.

**Статусы находки:** нарушено; норма (для отчёта о покрытии); проверить вручную (графика, инженерное суждение);
проверить невозможно (нет входа, нечитаемо, нет данных). Правило, которому не хватает входа, обязано вернуть
«проверить невозможно», а не промолчать.

**Доказательство:** у каждой находки есть якоря (sha256 файла, страница, рамка в пт; путь XML; ячейка; GUID),
сравниваемые значения, основание из индекса норм, а для фактов от LLM — извлекатель и уверенность.

**Grounding-гейт отчёта** (паттерн procdesk `protocol/generate.py`):
- каждое число в тексте находки входит в факты пакета;
- каждая ссылка на норму есть в индексе и действует на дату подачи;
- каждая цитата совпадает с текстом по якорю.

Не прошло — находка не выходит, прогон помечается.

**Выпуск правила:** фикстуры зелёные → метрики на засеянном корпусе в пределах гейта → рецензия практика.
До рецензии находки правила помечаются в отчёте «не проверено практиком».

## Почему

- Карточки превращают отсутствие предметных знаний в процесс: учимся, когда пишем правило.
- Фикстуры — аналог тестбенча в EDA: набор проверок с эталонами и есть ров, который не скопировать промптом.
- «Проверить невозможно» отделяет честный продукт от правдоподобного.

## Последствия

- Правило без фикстур не регистрируется (проверка в тестах).
- Отчёт показывает покрытие: сколько правил применимо, сколько сработало, сколько не смогли проверить.
