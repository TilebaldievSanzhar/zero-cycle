# ADR 0005 — Движок правил: исходы, контекст, гейт, фикстуры

Статус: принято · 27.10.2026 · реализует [ADR 0004](0004-rules-evidence-grounding.md) на ступени 0 (шаг 0.5)

## Контекст

[ADR 0004](0004-rules-evidence-grounding.md) задал, что такое правило: код, метаданные и фикстуры. Там же —
статусы находок и требование доказательств. Нужно решить, как правило пишется, что ему доступно и где
проверяется доказательство. Первые правила — пакет `kz` (шаг 0.7k) и общие правила основной надписи.
Параллельно идёт рефакторинг контекста юрисдикции: справочник шифров и профиль основной надписи по редакции СПДС
([дополнение к ADR 0003](0003-jurisdiction-packs.md)).

## Решение

1. **Правило — функция `check(ctx) → исходы`** под декоратором `@rule(id, …метаданные…, fixtures=…)`.
   - Пакет правила — первая часть id: `kz.completeness.ird` → `kz`.
   - Модули правил — `zerocycle.packs.<пакет>.rules`.
   - Правило без фикстур не регистрируется.
2. **Исход (`Outcome`) — то, что правило сказало про один объект проверки:** пункт перечня, ссылку на норму,
   группу листов. В исходе — статус, текст, якоря, сравниваемые значения, своё основание (если уже основания
   правила) и ключ объекта `item`. Метаданные правила (тяжесть, семейство, версия) движок добавляет сам. Поэтому
   правило не может выдать находку «от чужого имени».
3. **Основание — по редакции.** Основание правила — общее или по редакции СПДС: `{«ГОСТ 21.101-97»: …,
   «ГОСТ Р 21.101-2020»: …}`. Одно правило основной надписи работает в РК и в РФ и ссылается на свой стандарт.
4. **Контекст проверки (`rules.Context`)** — пакет после описи, файлы на диске, параметры (вид работ),
   редакция СПДС. Тексты страниц движок читает сам и лениво, через pypdfium2: это быстро, и есть позиции символов.
   - Начало страницы (300 знаков) отличает документ от упоминания: «АПЗ» в заголовке листа — документ,
     «согласно АПЗ № …» в тексте записки — нет.
   - Ссылки на нормы собираются со всего текста пакета с рамкой обозначения на листе.
   - Опись (`scan`) для этого не расширяется: модель пакета остаётся моделью описи.
5. **Grounding-гейт — в движке, а не в правилах.** Находка задерживается, если:
   - у «нарушено» или «проверить вручную» нет якоря (кроме правил наличия: отсутствие доказывается перечнем
     просмотренного);
   - основание начинается не с документа из `rules/bases.toml`;
   - в тексте есть число, которого нет в значениях, основании, цитатах якорей или путях документов.

   Задержанное попадает в отчёт отдельным списком, прогон помечается.
6. **Список оснований (`bases.toml`)** — какие документы правила вправе цитировать и как каждый сверен: по
   тексту, по копии на сайте, по ссылкам экспертов. Несверенное допустимо, но видно в карточке правила.
7. **Индекс норм — данные пакета юрисдикции.** Например, `packs/kz/agsk1.json`: собирается скриптом из
   официального издания. Правило записывает, какой индекс и какой версии использовало, — это попадает в запись
   прогона.
8. **Покрытие** — по каждому правилу: применимо ли (юрисдикция, вид работ), сколько исходов каких статусов,
   упало ли. Упавшее правило не роняет прогон.

## Почему

- Исходы вместо готовых находок: тяжесть и семейство нельзя забыть или подменить в правиле, а гейт один для всех.
- Ленивые тексты через pypdfium2: пояснительная записка на 180 страниц читается за 0,4 с — второй проход по PDF
  дешевле, чем раздувать модель описи текстами всех страниц.
- Список оснований вместо свободного текста: «ссылка на норму, которой нет», — тот же класс ошибки, что
  выдуманная цифра.

## Последствия

- Новый пакет правил — модуль `rules.py` в папке пакета. Цепочку юрисдикции (`core` → `spds` → `kz`/`ru`)
  отдаёт контекст юрисдикции.
- Фикстуры гоняет общий тест для всех зарегистрированных правил. Карточки — `zerocycle rules --cards <папка>`.
- Отчёт — JSON и Markdown (`zerocycle check`); HTML с фрагментом листа — шаг 0.9.

## Дополнение 28.10.2026

После пакетов `spds` и `ru` (PLAN 0.6, 0.7, [CHECK_RU](../bench/CHECK_RU.md)):

1. **Фикстура проходит и через гейт.** Исход фикстуры, который гейт задержал бы в прогоне, — красная фикстура.
   Так нашлось правило со строкой «(графы 2 и 1)» без этих чисел в значениях.
2. **Индекс бывает неисчерпывающим** (`NormIndex.exhaustive`). АГСК-1 перечисляет все действующие документы своих
   видов, и «нет в индексе» там — «проверить вручную». Реестр «Стройкомплекс.РФ» — только документы
   с обязательными требованиями, и «нет в реестре» — «проверить невозможно» одной сводной находкой. Записи
   курируемых замен несут своё основание (`NormRecord.basis`), его проверяет гейт.
3. **Факты из текста собирает контекст проверки, а не правило:** ссылки на нормы и строки ведомости «Состав
   проектной документации». Одни и те же строки состава видят правило ПП 87 и правило «Состав ПД» ↔ тома.
4. **Сверка с эталоном — часть движка правил** (`rules/recall.py`, `zerocycle recall`). Дефект найден, если
   правило из его детекторов дало «нарушено» на месте дефекта: файл, лист, обозначение, GUID, раздел.
   «Проверить вручную» на том же месте — отдельный столбец. Ложная тревога — любое другое «нарушено»; «нарушено»
   другого правила на листе дефекта — сопутствующее. Отложенный набор сидов меряется один раз, после настройки.
