# Протокол бенчмарка v1 (черновик)

> Версия 0.1 · 23.10.2026. Протокол замораживается до первого прогона рук (PLAN, шаг 0.12); после заморозки
> меняется только новой версией с объяснением причин.

## Вопрос

Даёт ли «Нулевой цикл» прирост над сильной связкой «Claude Code + MCP» на проверке **пакета** проектной
документации — по полноте, точности, честности ссылок, воспроизводимости и цене?

## Корпус

| Слой | Что | Эталон | Зачем |
|---|---|---|---|
| Засеянный | 20–30 синтетических пакетов РФ: ПДЭ, тома PDF с основными надписями, «Состав ПД», ПЗ с ТЭП и ссылками на нормы; 300–1 500 листов на пакет | подсаженные дефекты | recall и точность по видам дефектов |
| Реальный публичный | 20–30 ПСД из вложений госзакупок РК — пакеты, прошедшие экспертизу | нет; находки оценивают вслепую | ложные тревоги на 100 листов, устойчивость разбора |
| Отказ | нечитаемые сканы, пакет без «Состава ПД», без ПЗ | «проверить невозможно» | честность |
| Реальный партнёрский (ступень 1) | прошлые пакеты партнёров с письмами замечаний | замечания экспертизы и слепая оценка | recall реальных замечаний |

**Дефекты засеянного слоя** фиксируются до разработки правил:
- из `bim-data/taxonomies/remark_and_defect_taxonomy.json`: D01 (ТЭП в ПЗ ≠ чертежи), D02 (лист есть в ведомости,
  но нет в комплекте), D03 (шифр в основной надписи ≠ обозначение комплекта), D07 (ссылка на недействующую
  редакцию СП), D09 (раздел требуется, но его нет в составе), D10 (нет даты или подписи, изменения не отражены);
- формальные: пропуск в нумерации листов; «Листов» ≠ фактическому числу; стадия «Р» в ПД; разные наименования
  объекта в томах; раздел ПП 87 без тома; том вне «Состава ПД»; имя файла ПДЭ не по обозначению; повтор GUID
  в info.xml; формат в графе 26 ≠ размеру страницы.

В корпус намеренно входят дефекты вне v1 (графика, инженерные нормы): правильный ответ на них — «проверить вручную».

**Отложенная выборка:** 30% пакетов на шаблонах и формулировках, которых нет в разработке. В разработке
на неё не смотрим.

## Руки

| Рука | Что |
|---|---|
| A0 | Claude Code: файловая система, инструменты PDF (текст и рендер страниц), толковый системный промпт с задачей и форматом ответа |
| A1 | A0 + скилы, написанные по публичным правилам (ГОСТ Р 21.101-2020, ПП 87): сильная самодельная версия. Сравнение с ней защищает от упрёка в «соломенном чучеле» |
| C | «Нулевой цикл» без агента: `zerocycle check` |
| B | агент A0, который вызывает «Нулевой цикл» через MCP |
| абляции | C без индекса норм; C без увязки; B без grounding-гейта |

Все руки отвечают в одной JSON-схеме: категория, документ, страница, описание, основание.

## Метрики

| Метрика | Как считать |
|---|---|
| Recall и точность по видам дефектов | находка ↔ дефект: тот же документ и страница (±1), та же категория; спорные случаи — слепая оценка |
| Строгое решение пакета | все дефекты найдены и ни одной критичной ложной находки |
| Ложные тревоги на 100 листов | реальный публичный слой, слепая оценка двумя оценщиками |
| Выдуманные ссылки и числа | ссылки сверяются с индексом норм, числа — с фактами пакета |
| Полнота доказательств | доля находок с якорем и основанием |
| Воспроизводимость | пересечение множеств находок в 5 прогонах (коэффициент Жаккара) |
| Честный отказ | доля «проверить невозможно» на слое отказа |
| Стоимость и время | доллары и минуты на пакет; стоимость одной верной находки |

## Процедура

1. Заморозить корпус и отложенную выборку; записать sha256 всех файлов.
2. Записать версии моделей, промптов, скилов и движка.
3. По 5 прогонов на пакет и руку; температура и бюджет токенов фиксированы.
4. Доверительные интервалы — бутстреп по пакетам.
5. Публиковать все руки, включая задачи, где связка выиграла.

## Внутренние гейты (не обещание рынку)

Рука C на dev-части засеянного слоя: recall формальных дефектов ≥ 0,9; ноль выдуманных ссылок и чисел;
детерминированные правила воспроизводимы в 5 прогонах из 5.

## Угрозы валидности

| Угроза | Ответ |
|---|---|
| Мы сами придумываем дефекты, которые умеем ловить | список дефектов фиксируется до правил; отложенные шаблоны пишутся отдельно; в корпусе есть дефекты вне v1 |
| Синтетика легче реальности | реальный публичный слой; со ступени 1 — пакеты партнёров |
| Оценщики знают, чья находка | находки перемешиваются и обезличиваются перед оценкой |
| Разные инструменты PDF у рук | A0, A1 и B используют одни и те же инструменты чтения PDF |
