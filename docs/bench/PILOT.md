# Пилот бюджета (PLAN 0.12, PROTOCOL v0.2 — «Пилот до заморозки»)

> 29.10.2026 · пилот в урезанном объёме — по решению владельца, из-за лимитов подписки: одна рука — один прогон, два
> пакета. Прогоны пилота в результаты бенчмарка не входят.

## Ответ для бюджета

**Стоимость прогона** — Opus 5.5, усилие Claude Code по умолчанию, цены API:

| Рука | 323 листа | 1 318 листов | Модель стоимости |
|---|---|---|---|
| A0 — агент | $2,73 · 7,5 мин | $3,54 · 8,7 мин | $2,46 + $0,82 на 1 000 листов |
| A1 — агент со скилами | $1,75 · 4,0 мин | $2,99 · 9,4 мин | $1,35 + $1,25 на 1 000 листов |
| B — агент с «Нулевым циклом» через MCP | $1,16 · 3,7 мин | $1,43 · 7,3 мин | $1,08 + $0,27 на 1 000 листов |
| C — «Нулевой цикл» без агента | $0 · 0,3 мин | $0 · 1,0 мин | — |

Скилы A1 стоят $5,23 разово: 2 сессии автора, 17 минут.

**Ёмкость подписки** (замер по соседним последовательным прогонам):
- пятичасовое окно вмещает около **$21** работы Opus 5.5 по ценам API;
- неделя — около **$175**;
- перерасход на аккаунте отключён: при исчерпании окна прогон обрывается, и потраченное пропадает. Так ночью
  пропал один прогон за $2,37.

**Полный прогон** (средний пакет — 700 листов; 11 пакетов — минимум отложенной части: 80 дефектов при 7,5 на пакет):

| Сценарий | $ по ценам API | Пятичасовых окон | Недель подписки |
|---|---|---|---|
| минимум: A1 и B, 11 пакетов × 3 прогона | 115 | 5,4 | 0,7 |
| A0, A1 и B, 11 пакетов × 3 прогона | 215 | 10,1 | 1,2 |
| A0, A1 и B, 11 пакетов × 5 прогонов | 359 | 16,8 | 2,0 |
| A0, A1, B и B1, 20 пакетов × 5 прогонов | 1 001 | 46,8 | 5,7 |

**Вывод.** На подписке бенчмарк возможен только в минимальном или сокращённом виде — и он займёт её целиком на
несколько дней. Сценарий A0, A1 и B, 11 × 3 — это $215 по ключу API или неделя с лишним подписки. Пилот (урезанный,
с ночными потерями) стоил около $23.

## Что меряли

Пакеты — разработочная часть слоя S (генератор v1), разного объёма и на разных шаблонах организаций:
- v1-dev-0222 — 323 листа, шаблон compact, 10 дефектов;
- v1-dev-0224 — 1 318 листов, шаблон cad-long, 5 дефектов;
- v1-dev-0212 — 667 листов, шаблон gost, только рука C: агентский прогон ночью оборвал лимит.

RS ещё нет (шаг 0.4c), поэтому на реальных пакетах стоимость не мерили.

Агентские руки — Claude Code без интерфейса (`claude -p`, `bench/pilot.py`):
- одна задача и одна схема ответа (`bench/arms.py`), одни инструменты: Bash, Read, Write, Edit, Glob, Grep, Skill; веба
  нет;
- Python для PDF — системный, без кода «Нулевого цикла»;
- папка руки — вне репозитория, со случайным именем, после прогона удаляется;
- у A1 — скилы, у B — MCP-сервер с корнем в этой папке.

Скилы A1 писала отдельная сессия Claude Code только по публичным источникам `bim-data` — ГОСТ Р 21.101-2020, ПП № 87 и
№ 145, приказ 783/пр и письма Минстроя, выгрузка реестра «Стройкомплекс.РФ»:
- два скила: `pd-expertise-precheck` и `ntd-actuality-check`;
- пять скриптов;
- выписки по ПП 87 и реестру.

Скилы лежат в `var/bench/pilot/results/skills_A1/`.

Сопоставление — по протоколу, без знания правил движка:
- тот же документ и страница ±1;
- категория из допустимых проявлений;
- у дефектов отсутствия — раздел, обозначение или GUID.

На руке C оно даёт то же, что `zerocycle recall`: 40 из 40 на шести пакетах.

## Что увидели (сигналы, не результаты)

| Рука | Recall, 323 / 1 318 | Точность, 323 / 1 318 | Ложных, 323 / 1 318 (на отвлекающем) |
|---|---|---|---|
| A0 | 0,90 / 0,80 | 0,63 / 0,17 | 7 (7) / 19 (16) |
| A1 | 0,90 / 0,80 | 0,63 / 0,10 | 7 (7) / 38 (17) |
| B | 1,00 / 1,00 | 0,91 / 0,83 | 1 (1) / 1 (0) |
| C | 1,00 / 1,00 | 0,91 / 1,00 | 1 (1) / 0 |

Подробнее:
- **A0 и A1 пропустили F08** — формат в графе 26 не совпадает с размером страницы — на обоих пакетах. Зато обе руки
  приняли за этот дефект печать с уменьшением: 14 ложных тревог на 1 318 листах у каждой.
- **У A1 21 ложная тревога — «нет подписи в графе 12».** По ГОСТ Р 21.101-2020 (прил. Ж, примечание 1) в электронном
  документе подпись — электронная, и пустая графа не дефект. Скилы этого не знали.
- **У B одна ложная тревога на каждом пакете.** На 323 листах её дал движок: СНиП в наименовании СП на листе боком.
  Причина в правиле — оно не учитывает поворот страницы; соседняя сессия исправила это в отдельной ветке и внесёт в
  main после пилота. На 1 318 листах тревога была по делу — см. дефекты генератора ниже.
- **Руки нашли два настоящих дефекта генератора**, их никто не засевал:
  - содержание тома 12 «Смета» не помещалось на лист: строки локальных смет шли поверх основной надписи;
  - листы «План эвакуации 22-го этажа» в 16-этажном доме.

  Это верные находки, засчитанные как ложные. Генератор исправлен: локальные сметы в содержании — одной строкой,
  номер этажа — не выше этажности. Корпус к заморозке пересоздаётся.
- **Изоляция.** Ни одна рука не читала репозиторий, корпус или эталон. A0 и B складывали черновики в папку уровнем
  выше и во временную папку Windows. Теперь временная папка руки — внутри её папки, а аудит отмечает подъём `..`.
- **Сбои:** у агентских рук не было ни переполнений контекста, ни ответов не по схеме. Были только обрывы по лимиту
  подписки.

## Что решить при заморозке

1. **Бюджет и канал.** Ключ API с бюджетом около $250 под сценарий A0, A1 и B, 11 × 3, — или подписка: тогда
   минимальный сценарий займёт около 5 пятичасовых окон.
2. **Модель и усилие.** Opus 5.5 с усилием по умолчанию. Дороже всего в пилоте обошёлся прогон A0 на 1 318 листах —
   $3,54, так что потолок $8 на прогон — с запасом.
3. **Прогоны:** 3. Разброс в пилоте не мерили — у каждой руки было по одному прогону.
4. **Скилы A1:** окончательные — отдельной сессией в бюджет одного рабочего дня. Пилотные писались 17 минут.
5. **Задача рукам:** добавить «черновики — только в текущей папке».

## Как повторить

```powershell
# скилы A1 — отдельная сессия по публичным источникам; --resume продолжает оборванную
.venv\Scripts\python.exe -m zerocycle bench author var/bench/pilot/results --bim-data ../bim-data --budget 15

# руки; на подписке --start-below: перед прогоном мерить окно и при нехватке места ждать сброса
.venv\Scripts\python.exe -m zerocycle bench run var/bench/pilot/results --corpus var/bench/pilot/corpus `
  --packages v1-dev-0222,v1-dev-0212,v1-dev-0224 --arms C,A0,A1,B --runs 2 --model claude-opus-5-5 `
  --budget 15 --skills var/bench/pilot/results/skills_A1 --parallel 1 --start-below 0.8

# оценка, таблица стоимости и прогноз → var/bench/pilot/results/report.md
.venv\Scripts\python.exe -m zerocycle bench score var/bench/pilot/results --corpus var/bench/pilot/corpus
```

`bench run` повторяет только неуспешные прогоны: успешные пропускаются, а оборванные лимитом идут заново. Корпус пилота
пересоздаётся командой `zerocycle gen var/bench/pilot/corpus --v1 --seed 222` (затем сиды 212 и 224). После исправления
генератора пакеты будут другими.
