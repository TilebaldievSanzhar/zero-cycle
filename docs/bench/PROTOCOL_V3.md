# Протокол бенчмарка V3

> Черновик 0.1 · 17.11.2026. Замораживается после пилота, до первого прогона на отложенной части; после заморозки
> меняется только новой версией с объяснением причин. Основа — [REVIEW_2026-11, § 4 и § 9](../product/REVIEW_2026-11.md#4-бенчмарк-v3),
> корпус — [DATASET_V3](DATASET_V3.md). Решение владельца 17.11: пилот и прогоны — на Codex.

## Вопрос и главная гипотеза

Находит ли агент с «Нулевым циклом» v2 больше документов, которые эксперты РК заставили добавить, чем тот же агент со
скилами по открытым нормам?

**H5 — главная** (решение владельца 09.11): рука B′ — Codex и движок v2 через MCP, рука A1 — Codex и скилы по открытым
нормам. От скилов движок v2 отличается знанием экспертизы: какие документы эксперты требуют по видам объектов и
разделам. Это знание собрано из размеченных пунктов заключений РК ([LABELING](LABELING.md#рк-в-масштабе--1311)).

Три исхода на отложенной части — предложение, окончательно δ фиксируется при заморозке:

| Исход | Условие | Что дальше |
|---|---|---|
| H5 подтверждена | полнота B′ − A1 ≥ δ, нижняя граница 95% интервала > 0, и точность не хуже: нижняя граница интервала разницы точности > −0,05 | движок стоит больше скилов: канал продукта — агент с MCP |
| H5 опровергнута | верхняя граница интервала разницы полноты < δ: прироста δ и больше нет | условие остановки REVIEW § 9, п. 4: ценность ищем в вариантах C и D (REVIEW § 3) |
| Не решено | остальное | решение владельца: расширить корпус или признать, что крупного прироста нет |

Предложение — δ = 0,10. Три исхода, а не два, потому что выборка мала (см. «Мощность»): без интервала «не подтверждена»
легко принять за «опровергнута».

**H3:** ложных тревог руки B′ на реальных пакетах не больше порога на 100 листов. Порог фиксируется после пилота,
ориентир — 1 на 100 листов.

Вторичные сравнения, без вывода «подтверждено»: B′ против A0, A1 против A0, два порядка работы B′ (в пилоте), полнота по
группам видов документов и по видам объектов. При любом исходе публикуем все руки.

### Мощность

Симуляция на составе отложенной части: 38 дефектов в 30 кластерах, по два прогона A1 и B′, парный бутстреп по
кластерам, δ = 0,10. Допущения: вероятность найти дефект у A1 распределена равномерно от 0 до 1, B′ прибавляет к ней
одно и то же.

| Истинный прирост полноты | 0 | 0,10 | 0,20 |
|---|---|---|---|
| исход «подтверждена» | 0,03 | 0,33 | 0,77 |
| исход «опровергнута» | 0,39 | 0,04 | 0 |
| то же на 80 дефектах: «подтверждена» / «опровергнута» | 0,03 / 0,60 | 0,47 / 0,03 | 0,97 / 0 |

V3 надёжно различает только крупный прирост, около +0,2. При приросте 0,10 в двух случаях из трёх итог — «не решено».
Больше дефектов делает исход определённее: на 80 дефектах прирост 0,20 подтверждается почти всегда, а отсутствие
прироста опровергается в 60% случаев вместо 39%. Добрать дефекты можно из оставшихся 62 закупок РК и из РФ
(DATASET_V3, «Что дальше») — решение владельца до заморозки. Третий прогон даёт меньше (прирост 0,20: 0,77 → 0,90), а
один прогон вместо двух снижает вероятность подтвердить прирост 0,20 до 0,47: повторы A1 и B′ при сокращении не трогаем.

## Руки

Одна семья — Codex (решение владельца 17.11): `gpt-6.1-sol`, усилие `high` (предложение; если пилот покажет, что не
укладываемся в лимит, — `medium` у всех рук), одна версия codex-cli на весь основной прогон. Находки рук Codex оценивает
Claude.

| Рука | Что |
|---|---|
| A0 | Codex: задача, пакет, Python для чтения PDF, Excel и Word. Может писать и запускать свой код |
| A1 | A0 + скилы в `.agents/skills` папки прогона. Их пишет отдельная сессия Codex по открытым нормам — тем же, на которых стоит движок v2 (ГОСТ 21.101-97, приложения Приказа № 299, АГСК-1, СН РК 1.02-03-2022, если движок им пользуется). У автора нет кода «Нулевого цикла», заключений и пакетов. Бюджет — около часа работы агента. Скилы публикуются с результатами |
| B′ | A0 + движок v2 через MCP (`zerocycle mcp`). Сервер отдаёт и находки, и отчёт о покрытии: что проверено, чего движок не проверял (REVIEW § 9, п. 3). Скилов A1 у B′ нет |

**Два порядка работы B′ — в пилоте:** «движок первым» (сначала `check_package`, потом своя проверка) и «агент сначала»
(сначала сам, потом сверка с движком). В основной прогон идёт порядок с большей полнотой в пилоте, при равенстве —
«агент сначала»: на реальных пакетах рука B «якорилась» на движок (REVIEW § 1.2). Правило записано до пилота.

**Одинаково у всех рук:** текст задачи и схема ответа (`bench/v3run.py` на коммите заморозки), Python без кода
«Нулевого цикла», без интернета и веб-поиска, потолок времени на прогон (предложение — 60 мин; уточняется в пилоте).
Запуск — `codex exec --ignore-user-config --ephemeral --skip-git-repo-check` с профилем прав вместо старого флага
песочницы (см. «Обвязка»). В папке прогона только `package/` (у A1 — ещё скилы, у B′ — настройка MCP); эталон и
заключения — вне её и закрыты для чтения.

## Как засчитываем

**Найденный дефект.** В находке назван документ того же вида и есть признак отсутствия: слова «нет», «отсутствует»,
«не представлен»… (как в `bench/real.py`) или категория «комплектность». У «прочих расчётов» должно быть видно, какой
расчёт: КЖ, гидравлический, водоснабжение и водоотведение, дымовая труба, продолжительность строительства. Одна находка —
один дефект: два энергопаспорта двух школ в kz-39 требуют двух находок или одной, где названы обе. Все совпадения и
почти-совпадения (документ назван, отсутствие — нет) просматриваются глазами без имени руки.

- Засчитывается находка любого статуса — «нарушение» или «проверить вручную»: ГИП проверит и то и другое. Вторично —
  только «нарушения».
- Значение руки на дефекте — доля её прогонов, где дефект найден; полнота — сумма по дефектам на число дефектов.

**Находки вне засева** — не ложные автоматически: прошедший экспертизу пакет всё равно содержит дефекты. Их оценивает
Claude (`claude-opus-5-5`, усилие `high`) вслепую: находки перемешаны и обезличены, оценщик видит пакет и те же нормы, что
автор скилов. Вердикт — подтверждено / не подтверждено / проверить нельзя; важность — «снял бы эксперт» или «мелочь».
Выборка — 40 находок каждой руки, случайно, сид 2026. Когда появится практик — его разметка выборки и каппа Коэна с
оценщиком.

## Метрики

| Метрика | Как считать |
|---|---|
| Полнота — главная | найденные дефекты отложенной части к их числу; по рукам, парно |
| Полнота по группам и видам объектов | сметные документы отдельно от остальных — из-за перекоса; здания, линейные, благоустройство. Отчёт говорит, откуда прирост |
| Точность | подтверждено / (подтверждено + не подтверждено) по слепой оценке |
| Ложные тревоги на 100 листов (H3) | доля не подтверждённых × число находок руки / листы PDF × 100 |
| Стабильность | коэффициент Жаккара находок двух прогонов A1 и B′ на пакете |
| Расход | токены (ввод, кэш, вывод, рассуждение) из событий `codex exec`, доля лимита, минуты |

Интервалы — перцентильные 95%, парный бутстреп по кластерам (группа или пакет), 10 000 повторов, сид 2026.

## Пилот

- **Состав:** все 6 пакетов разработки; руки A0, A1, B′ «движок первым», B′ «агент сначала» — по одному прогону, 24
  прогона. Прогоны пилота в результаты не входят.
- **Проверяем:** обвязку на реальных пакетах (форматы, песочница Windows, MCP, скилы в `.agents/skills`), схему ответа,
  сопоставление, слепую оценку — на 10 находках каждой руки.
- **Записываем на прогон:** токены, долю лимита, минуты, вызовы инструментов, сбои.
- **Выход:** расход по рукам и объёму пакета, прогноз основного прогона в днях подписки, порядок B′, δ и порог H3 —
  на решение владельца до заморозки.

## Основной прогон

33 отложенных пакета × (A0 — 1 прогон, A1 — 2, B′ — 2) = 165 прогонов. Порядок: повтор → пакет → рука — если время
кончится, сравнение останется парным. Сбой прогона (таймаут, ответ не по схеме) — пустой ответ; прогон, оборванный
лимитом, повторяется и в оценку не входит. Если прогноз выше допустимого срока, сокращаем по порядку: A0 → число
пакетов, но не ниже 25 дефектов. Повторы A1 и B′ не сокращаем.

**Заморозка** фиксирует: δ, порог H3, порядок B′, усилие, версии codex-cli и модели, задачу и схему, скилы A1, движок v2
и его знание (sha256), sha256 эталона отложенной части.

## Где запускать: локально или облачный Codex — 17.11

Вопрос владельца: можно ли гонять в облаке Codex так, чтобы не перезапускать прогоны вручную. Проверено по документации
и на codex-cli 0.169.0 этой машины.

| Что | Как в облаке Codex |
|---|---|
| Запуск из командной строки | есть, помечен как экспериментальный: `codex cloud exec --env <среда> [--attempts 1–4] [--branch …] "<задача>"`, затем `codex cloud status`, `list --json`, `diff`, `apply` ([CLI][codex-cli]) |
| Среда | репозиторий GitHub, скрипт установки с интернетом; у агента интернет по умолчанию выключен; диск на Plus — 8 ГиБ ([среды][codex-env]) |
| MCP | для облачных задач не описан; в документации MCP: локальные серверы в облаке могут быть недоступны ([MCP][codex-mcp]) |
| Модель и усилие | у `codex cloud exec` ключей нет; выбор — в веб-интерфейсе. Закрепить `gpt-6.1-sol` и усилие на 165 прогонов проверяемо нельзя |
| Лимит | общий с локальным; облачная задача может тратить его больше, чем локальная ([цены][codex-pricing]) |
| Расписание | запланированной задаче с файлами компьютера нужны включённый компьютер и запущенное приложение. Облачную задачу на своём репозитории по расписанию документация не описывает; в облаке по расписанию идут Team Tasks — это командный тариф ([расписание][codex-auto]) |
| Запуск по cron без ноутбука | только обходом: GitHub Actions с учёткой ChatGPT в секретах. Для автоматизации документация рекомендует ключ API, а `auth.json` велит беречь как пароль ([вход][codex-auth]); Action Codex работает с ключом API ([Action][codex-action]) |
| Изоляция | облачный агент видит весь репозиторий, в том числе `bench/v3.py` с засевом: нужен отдельный репозиторий только с пакетом |

**Вывод.** Облако освобождает ноутбук, но не лимит. Руку B′ там пришлось бы давать иначе, чем локально, а модель и
усилие — не закрепить. Основной прогон — локально. Чтобы не перезапускать вручную:
- драйвер сам ждёт сброса лимита: время берёт из ошибки «try again at …», как разметка с `--wait`;
- задание планировщика Windows «при входе в систему» поднимает драйвер, свёрнутым окном (скрытое окно в v1 уводило
  процессы на медленные ядра); замок не даёт запустить вторую копию;
- итоги пишутся после каждого прогона, повторный запуск продолжает с места.

От владельца — только включённый ноутбук: настроить один раз. Облако проверяем в пилоте 2–3 прогонами A0 через
`codex cloud exec`: расход лимита и как забрать ответ. Если в облаке появятся MCP и выбор модели — вернёмся к вопросу.
На тарифе Pro нет пятичасового окна ([цены][codex-pricing]): ждать пришлось бы реже.

## Обвязка — 18.11

Драйвер — `python -X utf8 -m zerocycle.bench.v3run run --plan check|pilot|main`; ещё `status`, `probe sandbox|skills`,
`autostart --install|--remove`. Засчитывание — `python -X utf8 -m zerocycle.bench.v3score <план>`: `report.md` и
`review.md` — совпадения вперемешку, без имени руки. Итоги — `var/v3/runs/<план>/`.

**Изоляция руки** — песочница Codex на Windows в режиме `elevated` и профиль прав, заданный в командной строке:
- читать можно всё, кроме закрытого: папки репозитория с корпусом, эталоном, разметкой, кодом засева и историей git
  (`var`, `src`, `docs`, `tests`, `scripts`, `.git`), соседние папки рабочего пространства, `C:\zc-bench`, `.codex`,
  `.claude`, черновики Claude Code, личные папки;
- писать — только в своей папке `C:\zc-v3\work\<прогон>`; временные файлы — туда же;
- сети нет; веб-поиск, плагины, приложения, браузер, управление компьютером, картинки и память выключены;
- Python — системный, без окружения проекта: рука не может импортировать движок.

Три находки при настройке:
- **Ключ `-c` Codex делит по точкам без учёта кавычек:** путь с точкой («.codex») ключом не задать. Профиль передаётся
  одной TOML-таблицей.
- **Запрет на корне репозитория не действует.** Прежние сессии Codex с рабочей папкой в репозитории оставляют на нём
  явное разрешение группе песочницы, и оно перекрывает унаследованный запрет. Запрет ставится на каждую папку: явный
  запрет на самой папке идёт раньше. В корне остаются `pyproject.toml`, README и кэши — ответов там нет.
- **Запреты общие для всей группы песочницы.** Обычная сессия Codex на этой машине может снять их, пока идёт прогон.
  Поэтому перед каждым прогоном — бесплатная проверка `codex sandbox` без модели: своя папка читается и пишется, код
  засева, эталон, git, `.codex` и `.claude` не читаются, запись в репозиторий не проходит. Не прошла — прогон ждёт.
  Пока идут прогоны, Codex на этой машине лучше не запускать.

**Проверки среды 18.11** (`probe`, около 50 тыс. входных токенов вместе): Python с pdfplumber, pypdfium2, openpyxl и
python-docx работает; чтение `pyproject.toml` из репозитория — «Access is denied»; запись в своей папке проходит. Скил
из `.agents/skills` Codex находит; скилы плагинов (Notion, Sites…) после выключения плагинов исчезли.

## Угрозы валидности

| Угроза | Ответ |
|---|---|
| Сборщик корпуса видел все пакеты и знает засев отложенной части | знание движка — скриптом из разметки без отложенных заключений; правил под имена файлов отложенных пакетов нет; движок замораживается (sha256) до прогонов на отложенной части |
| Знание движка и засев — из одного корпуса заключений | `knowledge_exclude`; знание сводное по видам объектов |
| Ответ виден в пакете: копия заключения, пометки, титул «откорректировано по замечаниям» | HIDDEN, чистка имён, проверка текста первых листов (`leak_suspects`); подозрения отложенной части просматриваются до заморозки |
| Пакет после экспертизы: остальные замечания уже исправлены | пакет чище настоящего «до экспертизы»; полнота — по тем видам замечаний, что засеяны |
| Половина дефектов — сметные ведомости | полнота по группам; отчёт говорит, откуда прирост |
| Одна семья агентов | выводы — про Codex; Claude только оценивает |
| Оценщик ошибается | слепая оценка; выборка практику, когда он появится |
| Codex обновляется посреди прогона, модель снимают | версия CLI закреплена и пишется в каждый прогон; смена модели — новая версия протокола |
| Малая выборка | мощность посчитана заранее; три исхода вместо двух |
