# MCP-сервер «Нулевого цикла»

> PLAN, шаг 0.13. Сервер отдаёт движок проверки агенту — Claude Code, Cursor, любому клиенту MCP. Это рука B
> бенчмарка: агент со своими инструментами чтения PDF плюс «Нулевой цикл» ([PROTOCOL](bench/PROTOCOL.md#руки)).
> Решения — [ADR 0006](adr/0006-mcp-server.md).

## Подключение

Сервер работает по stdio на этой машине: пакет никуда не отправляется, внешней модели движок не вызывает.

```powershell
# из папки, где лежит пакет (или выше): --root . — дальше этой папки проверка не ходит
claude mcp add zerocycle -- uv run --project C:\Projects\development_challenge\zero-cycle python -m zerocycle mcp --root .
```

То же для проекта — файл `.mcp.json` в папке, откуда запускается агент:

```json
{
  "mcpServers": {
    "zerocycle": {
      "command": "uv",
      "args": ["run", "--project", "C:/Projects/development_challenge/zero-cycle",
               "python", "-m", "zerocycle", "mcp", "--root", ".", "--runs-dir", "runs"]
    }
  }
}
```

- `--root` — папка, за пределы которой проверка не выходит. В бенчмарке это `package/`: эталон лежит рядом,
  и агент не должен его видеть.
- `--runs-dir` — куда сохранять отчёты прогонов (JSON) для записи бенчмарка.
- На Windows со Smart App Control запускайте через `python -m zerocycle`: обёртку `zerocycle.exe` политика
  блокирует.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `check_package(path, jurisdiction="ru", work_kind=None, wait_seconds=50)` | опись и проверка папки или zip; сводка: находки по статусам, нарушения, что не проверено, какие правила не применялись |
| `run_status(run_id=None, wait_seconds=50)` | статус и сводка прогона; большой пакет проверяется минуты — агент спрашивает ещё раз |
| `list_findings(run_id, status, category, rule, document, offset, limit)` | находки с фильтрами |
| `explain_finding(finding_id)` | значения, все якоря, основание и как оно сверено, карточка правила: почему эксперт это ловит и как сформулирует замечание |
| `render_fragment(finding_id)` | PNG листа с красной рамкой находки — проверить глазами; без находки — лист по `file` и `page` |
| `list_rules(jurisdiction)` | правила юрисдикции, основания и применимость — и чего движок не проверяет |
| `norm_status(designation, jurisdiction)` | действует ли документ по индексу: реестр «Стройкомплекс.РФ» для ru, АГСК-1 для kz |

Находка приходит в схеме ответа рук бенчмарка: `category`, `document`, `page`, `description`, `basis`. Кроме того:
- `id` — F1, F2… внутри прогона;
- `status`, `severity`, `rule`;
- `pages` — все листы якорей.

Статусы:
- `violated` — нарушение с листом и основанием;
- `manual` — нужен человек;
- `cannot_check` — движок не смог проверить: нет текстового слоя или данных; это не «норма»;
- `ok` — проверено, замечаний нет.

## Как это выглядит

Пакет Тауыш, 1 049 листов, `jurisdiction="kz"`, через stdio:
- первый вызов `check_package` за 10 с вернул `state: running`;
- после пяти вызовов `run_status` — `done` за 181 с: 26 нарушений, 29 «проверить вручную»;
- «не проверено»: 1 794 ссылки на ГОСТ и 380 на ЭСН РК — АГСК-1 их не перечисляет; ведомости «Состав проекта» нет;
- `explain_finding("F1")` — чужое место строительства в 36 штампах;
- `render_fragment("F1")` — графа 2 листа с рамкой (PNG, 45 КБ);
- `norm_status("СП РК 2.02-101-2014", "kz")` — заменён на СП РК 2.02-101-2022.

## Чего пока нет

- **HTTP-транспорта.** Для веба и плагина САПР — ступень 2, обвязка как в second-key (Streamable HTTP, токен).
- **Решений ГИПа** («принято / отклонено» по находке) — вместе с отчётом 0.9.
- **Прогресса по шагам описи.** Агент видит только «идёт» и прошедшие секунды.
