# Нормоконтроль пакета ПСД (РК) перед экспертизой

Скил даёт: скрипты автоматического поиска кандидатов в замечания, справочники, выписанные **только** из
ГОСТ 21.101-97, приложений 2, 3, 4, 4-1, 5 к Правилам (Приказ № 299) и АГСК-1 (июнь 2025), и правила
оформления результата. Скрипты дают **кандидатов**; в findings попадает только то, что вы подтвердили по файлам.

`SKILL_DIR` = папка, где лежит этот SKILL.md (скрипты — `SKILL_DIR/scripts`, справочники — `SKILL_DIR/references`).

## Жёсткие правила
1. Читать только `package/` и файлы скила. Черновики, JSON и PNG класть в подпапку текущей рабочей папки
   (например `./_nk/`). Не искать файлы вне текущей папки, не ходить в сеть.
2. Основание замечания — только документы из справочников скила: `ГОСТ 21.101-97, п. …`,
   `Приложение N к Правилам … (Приказ № 299), п. …, пп. …)`, `АГСК-1 (июнь 2025), с. N PDF`. Не ссылайтесь на
   нормы, текста которых нет (СН РК 1.02-03-2022, ГОСТ 2.301, ГОСТ Р 21.101-2020 и т.п.) как на основание
   конкретного пункта; если без них нельзя — «проверить вручную» и пометка в summary.
3. Не выдумывать числа: значения, номера листов, страницы, шифры — только из файлов пакета и вывода скриптов.
4. Страницы — номера страниц PDF с 1 (не номер листа в штампе). `null` — замечание к документу целиком.
5. Путь документа — относительно `package/` (например `Том 2 АР.pdf`, `01_ИРД/АПЗ.pdf`).

## Порядок работы

### Шаг 1. Автоматический прогон
```bash
python SKILL_DIR/scripts/run_all.py package ./_nk --stage РП      # --kind new|reconstruction|capital_repair|smeta_correction|special
```
Создаёт в `./_nk`: `package.json` (форматы, поля штампов, скан-страницы), `text/*.txt` (текст с маркерами
`=== PAGE n ===` — грепайте), `titleblock.json`, `norm_refs.json`, `inventory.json`, `cross_check.json`.
Посмотрите сводку и список файлов пакета. Если `kind_guess` неочевиден — определите вид строительства по
заданию на проектирование/титулу и перезапустите `inventory.py` с `--kind`.

### Шаг 2. Комплектность → `inventory.json`, справочник `references/completeness_checklist.json`
- Вид строительства выбирает приложение: новое — прил. 2; реконструкция/расширение/модернизация/техперевооружение —
  прил. 3; капремонт — прил. 4; корректировка сметы без изменения решений — прил. 4-1; особое регулирование /
  экспертное сопровождение — прил. 5. Полные тексты: `references/prikaz299_prilozhenie_*.txt`.
- `verdict_hint = НЕ НАЙДЕН` для пункта `req=обязательно` → откройте список файлов и первые страницы похожих
  документов; если документа действительно нет — **«нарушение»**, основание — пункт приложения.
  Если документ только упомянут в ПЗ (`hits_body`), но не приложен — тоже «нарушение» (не приложен), в тексте
  укажите, где упомянут.
- Пункты `req=по условию` (СТУ, согласования, ЗСО, корректировка…) — «проверить вручную» только если по
  пакету видно, что условие наступило (например, уникальный объект, корректировка); иначе не записывать.
- Сведения, которые обычно подаются на Портале отдельно от PDF (реквизиты, документы о регистрации, сводная
  ведомость потребности в электронной форме) — при отсутствии «проверить вручную» с пояснением, если задача
  не говорит, что пакет полный.
- ТУ: `tu_by_type` показывает, на какие сети есть ТУ. Сопоставьте с сетями, которые проектируются (разделы
  ВК/НВК, ОВ/ТС, ЭС/ЭО/ЭН, СС, ГСН). Нет ТУ на проектируемое подключение → «нарушение» (прил. 2 п. 1 пп. 4)).
  Наличие схемы трассы к ТУ проверяйте визуально.
- **Состав проекта** (`sostav_proekta.missing`): том указан в «Составе проекта», но в пакете отсутствует →
  «нарушение» (документ — файл с «Составом проекта», страница — его страница; основание ГОСТ 21.101-97 п. 9.6 и
  прил. 2 п. 4 / прил. 3 п. 2 / прил. 4 п. 2). Обратная проверка: том есть в пакете, но не указан в «Составе
  проекта», или наименование/обозначение отличается от титула → «нарушение» (ГОСТ 21.101-97, прил. Р).
- **Содержание тома** (`contents_mismatch`): документ указан в «Содержании», но в томе его нет → «нарушение»
  (ГОСТ 21.101-97, п. 9.4). Также сверьте номера страниц в «Содержании» с фактическими.
- **Сметная документация** (`smeta`): нет ССР / объектных / локальных смет / ПЗ к смете при стадии РП →
  «нарушение» (ГОСТ 21.101-97, п. 3.2 е); прил. 2 п. 4). Конкретный обязательный состав сметной документации по
  СН РК 1.02-03-2022/АГСК-5 в источниках отсутствует — не утверждайте лишнего, укажите в summary.
- Обязательный перечень **разделов** РП (п. 15 Правил → СН РК 1.02-03-2022) в источниках отсутствует. Проверяйте
  разделы только против собственного «Состава проекта» пакета и явных требований приложений (например, ПОС —
  прил. 5 п. 11); остальное — в summary.

### Шаг 3. Оформление по ГОСТ 21.101-97 → `titleblock.json`, справочник `references/gost21101_checklist.md`
Для каждого кандидата откройте страницу и подтвердите:
```bash
python SKILL_DIR/scripts/render_page.py "package/<файл>.pdf" <стр> ./_nk/p.png --crop tb   # штамп; tr — номер стр.; full — лист
```
затем `Read ./_nk/p.png` (или `Read` самого PDF с `pages`). Что и как оценивать:
| check | Подтверждение | Статус |
|---|---|---|
| designation_missing | графа 1 пустая/нет обозначения | нарушение (прил. Д а); п. 4.1.3) |
| stage_missing | графа «Стадия» пуста | нарушение (прил. Д е)) |
| stage_mismatch | стадия на листе отличается от остальных | проверить вручную (прил. Д е)); «РП» само по себе не нарушение |
| sheet_seq / sheet_dup | пропуски/повторы номеров в графе «Лист» в пределах одного обозначения | нарушение (п. 9.3; прил. Д ж)) |
| sheets_total | «Листов» ≠ фактическому числу листов документа | нарушение (прил. Д и)). Учтите двустороннюю печать и то, что документ с тем же обозначением может быть разбит на файлы |
| sheets_total_repeated | «Листов» заполнено не на первом листе | проверить вручную (прил. Д и)) |
| role_incomplete / signature_check | нет фамилии, подписи или даты в строках Разраб./Пров./Н.контр./ГИП | после визуальной проверки: нет фамилии или даты — нарушение (прил. Д м)); подпись не видна — нарушение, если штамп явно пуст, иначе проверить вручную |
| page_numbering | сквозная нумерация страниц тома сбита (правый верхний угол) | нарушение (п. 9.3) |
| contents_missing | в томе несколько документов, нет «Содержания» | нарушение после просмотра первых страниц (п. 9.4) |
| title_signatures | на титуле нет подписи руководителя/гл. инженера организации и ГИП | нарушение после просмотра (п. 9.5) |
| format | нестандартный размер листа | проверить вручную (п. 4.1.4; прил. В — ГОСТ 2.301-68) |
| volume_size | превышено число листов в томе | нарушение (п. 4.1.4) |
| scan | нет текстового слоя | прочитать глазами (`Read` PDF/PNG), выполнить проверки вручную |
| titleblock_missing | нет основной надписи на листе | проверьте: титул/обложка не имеют штампа (п. 9.1–9.2) — тогда не дефект; иначе нарушение (п. 5.27) |

Дополнительно вручную (скрипты этого не ловят):
- обозначение на титуле тома = обозначению в штампах (п. 4.1.3); обозначение «Содержания» = обозначение + «.С»
  (п. 9.4), «Состава проекта» = базовое + «-СП» (п. 9.6);
- ведомость рабочих чертежей на листе «Общие данные»: перечень и наименования листов совпадают со штампами
  (п. 4.2.6; прил. Б, форма 1); есть ведомость ссылочных и прилагаемых документов (п. 4.2.5 б)); общие указания
  содержат запись о соответствии действующим нормам (п. 4.2.9 г));
- графа 4 (наименование изображений) соответствует надписям на чертеже (прил. Д г)).
Сканы и чертежи с векторным текстом без текстового слоя просматривайте выборочно: первые листы каждого
документа, каждый лист с кандидатом.

### Шаг 4. Увязка томов → `cross_check.json`
- `object_name_variants`: больше одного варианта наименования объекта → откройте места и сравните; разное
  наименование объекта/здания в графах 2–3 или на титулах (не перенос строки, не сокращение) → «нарушение»
  (ГОСТ 21.101-97, прил. Д б), в)); сравните также с заданием на проектирование и АПЗ.
- `tep` с `conflict=true`: убедитесь, что это один показатель одного объекта (а не помещения/очереди), тогда
  «нарушение»: «ТЭП не увязаны: <показатель> = X в <док, стр.> и Y в <док, стр.>». Основание — внутренняя
  несогласованность документации; норму-пункт можно указать как ГОСТ 21.101-97, п. 4.1.3/прил. Д только если
  речь о графах штампа, иначе в основании пишите «увязка томов (Том …, с. …)» без выдуманных пунктов.
- Сметная стоимость в ПЗ, ПЗ к смете и ССР должна совпадать; вид строительства в штампе (графа 3) — с заданием.

### Шаг 5. Ссылки на нормы → `norm_refs.json`, справочник `references/agsk1_notes.md`
- `replaced` → нарушение: «ссылка на заменённый документ <как в пакете>; по АГСК-1 действует <code> (с. N PDF)».
- `not_listed` → `grep` по `references/agsk1_2025-06_text.txt` (номер без года, без префикса); не нашли —
  нарушение «нет в перечне действующих АГСК-1 (июнь 2025)»; сомнения — проверить вручную.
- `out_of_scope` (ГОСТ, СТ РК, сметные нормативы) — не нарушение; перечислите в summary как непроверенные.
- Просмотрите и `text/*.txt` глазами на предмет нестандартных записей (СНиП без «РК», шифры, разорванные
  переносом), которые регулярка могла пропустить: `grep -n -E "СНиП|СН РК|СП РК|МСН|ВСН" ./_nk/text/*.txt`.

### Шаг 6. Ответ
Если в задаче задан формат — следуйте ему. Иначе JSON:
```json
{
  "findings": [
    {"document": "Том 1 ПЗ.pdf", "page": 4, "status": "нарушение",
     "issue": "В графе «Листов» основной надписи первого листа документа 2024-15-ПЗ указано 5, фактически 4 листа (стр. 4–7)",
     "basis": "ГОСТ 21.101-97, прил. Д, перечисление и)"},
    {"document": "Том 1 ПЗ.pdf", "page": 5, "status": "нарушение",
     "issue": "Ссылка на СН РК 1.02-03-2011*, заменённый СН РК 1.02-03-2022",
     "basis": "АГСК-1 (июнь 2025), с. 16 PDF: СН РК 1.02-03-2022 «Взамен 1.02-03-2011*»"}
  ],
  "summary": "Что проверено, что не удалось проверить и почему (ГОСТ/СТ РК вне АГСК-1, нет текста СН РК 1.02-03-2022, сканы без текста, подписи на N листах не видны и т.п.)"
}
```
Правила текста замечания: что не так + где (обозначение, лист/страница) + факт из файла (цитата/число).
Одно замечание — один дефект в одном документе; однотипные дефекты на многих листах одного документа
объединяйте в одно замечание со списком страниц (page — первая). Не включайте в findings «всё в порядке»,
догадки и рекомендации. Всё, что не проверено (и почему), — в summary.

## Ограничения скриптов
Эвристики штампа рассчитаны на текстовый слой и основную надпись в правом нижнем углу (200×65 мм).
Повёрнутые листы, штампы-картинки, сканы, нестандартные шаблоны → поля могут не распознаться: тогда
`tb.raw` пустой или без меток — проверяйте визуально. Отсутствие кандидата ≠ отсутствие дефекта: просмотрите
хотя бы первый лист каждого документа.
